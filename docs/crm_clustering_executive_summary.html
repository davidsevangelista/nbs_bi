1. Problem

NBS has 16,491 registered users with radically different behavioral profiles: some are high-volume onrampers generating meaningful spread revenue, others are DeFi traders who never converted BRL, others registered and never opened the app again. The existing segmentation (champion / active / at_risk / dormant) classifies users only by recency and revenue — it cannot distinguish how users use the product.

This project replaces that coarse classification with an ML-derived segmentation — mapping each user to a behavioral archetype — so that push campaigns can be targeted by product usage pattern, recency, and revenue profile simultaneously.

2. Approach

Feature extraction — 37 behavioral signals per user Six groups: lifecycle (signup age, onboarding status), onramp/offramp (volume, revenue, recency), card (spend, annual fee), DeFi/Solana (swaps, token diversity), international payouts, and engagement (AI sessions, notification read rate). Extracted directly from the production DB. No PII. Note: kyc_level is excluded from clustering features — it is effectively binary in this user base (0 = unverified, 2 = verified), collinear with all activity features. It is kept as a metadata column to drive the KYC-override messaging rule.
Preprocessing — log transform → StandardScaler → PCA Financial data follows power-law distributions. log1p compresses the tail without losing zeros. StandardScaler normalises scale across features. PCA retains 90.4% of variance in 12 components, eliminating correlated signals and preventing high-variance features from dominating the distance metric.
Outlier quarantine — HDBSCAN 4,089 users (24.8%) were removed before clustering — extreme profiles (very high spenders, bots, automated wallets) that would distort cluster centroids. Excluded from the push export.
K selection — silhouette score, Davies-Bouldin index, inertia elbow K-Means evaluated for k = 4–11. k = 8 maximised the silhouette score (0.000) — the clearest behavioural separation achievable in this user base.
Final clustering — K-Means + GMM validation + seed stability K-Means (k = 8, 20 restarts with k-means++ initialisation). Cross-validated against GMM (ARI = 0.694). Stability confirmed across 5 seeds — min pairwise ARI = 0.986.
Export — CSV with per-segment Brazilian Portuguese push copy 6,761 pushable users (active device token + delivery rules applied) exported with segment name, cluster ID, kyc_level, and ready-to-send push copy (title + body) for three time-of-day slots in Brazilian Portuguese. Users with kyc_level ≤ 1 receive a KYC completion CTA regardless of cluster.

6. KYC Override Rule

Users with kyc_level ≤ 1 (not yet fully verified) receive a dedicated KYC completion CTA regardless of their cluster assignment — the generic segment message is irrelevant to a user who has not completed verification. kyc_level = 2 means fully verified; those users always receive their segment copy.

Why as a delivery-layer rule, not a cluster? kyc_level was removed from clustering features — it is effectively binary in this user base (0 or 2), collinear with onboarding_completed and every activity feature. Including it would double-count information already captured by presence flags and transaction counts. It is retained as a metadata column in the export solely to drive this override.

7. Why PCA Before K-Means

The 37 input features were reduced to 12 principal components retaining 90.4% of total variance before clustering. This is required for K-Means to work correctly on this data:

  • Correlated features inflate distance. n_onramp_txns and total_onramp_brl are highly correlated — without PCA, both count in the Euclidean distance, effectively double-weighting onramp behaviour.
  • High-variance features dominate. Even after StandardScaler, residual correlation causes dominant features to overwhelm low-variance but meaningful signals like has_card or n_unique_tokens.
  • Curse of dimensionality. In high-dimensional spaces, Euclidean distances lose discriminative power. Reducing to 12 components restores meaningful geometry.

8. The 4,089 Quarantined Users

24.8% of users were removed before clustering. HDBSCAN flags users whose behavioral profile does not fit into any density region shared by at least 15 other users — typically extreme spenders, DeFi power users with automated transaction counts, or internal test accounts. These users are excluded from the push export and should be reviewed manually.

9. Monthly Refresh Protocol

Clustering artifacts (scaler, PCA, K-Means model, segment name mapping) are saved to data/processed/ versioned by month. New users can be scored without re-fitting: apply saved scaler → PCA → km.predict().

A full re-fit should run once per quarter or when the user base grows by more than 20%. After a full re-fit, cluster IDs shift — the segment name mapping must be manually re-reviewed against the heatmap.
